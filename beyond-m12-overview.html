Potluck: one presentation of the cell

The original idea -- Kubernetes for compute and attached hardware. Every board brings its sensors, cores and memory; the cell presents them all as one machine, on the house network, by itself; an integration layer lets any program see them the way it usually sees resources. A PC is welcome, never required. A discussion draft (BEYOND-M12.md), not built yet.

2 · The house network

Resource presentation

The whole cell, seen as one machine -- what Kubernetes' API server is to a cluster.

NodesResourcesCapacityAppsActorsModulesIntegrationsClientsEvents

Every value with its age and quality -- never a bare number. What is used, what is free, what runs where, what talks to what.

Presented by the cell itself

Board B, on the Wi-Fi, presents every board's resources: Home Assistant switches the lightbulb with no PC anywhere. Presenting is a role: give a second board Wi-Fi, and it takes over if B dies.

A PC, if there is one optional

Cabled to a board, its hub adds what a small board cannot hold: the full dashboard, history, your own programs. Switch it off and the cell, and Home Assistant's control of it, carry on.

3 · Integration layer

Adapters on the API

  • each resource named in the other program's own terms
  • age and quality kept: "unavailable", not a stale number
  • writes only where the package allows; never a deploy
  • chosen per cell, like an app -- on the PC, or on a board when it must be
  • its own state shown on the dashboard

With a PC, and without one

Without: board B connects out to the house's MQTT broker and presents the whole cell -- every board's lightbulb, LED and sensors -- to Home Assistant and any MQTT tool, read and controlled there. With: the PC's hub presents the same devices under the same names, plus the full dashboard, history and your own programs. Either can come and go; Home Assistant sees the same lightbulb throughout.

No network and no PC at all -- on a boat, in a field

The boards keep doing their jobs and helping each other; Potluck is just how they talk. When one high in the mast takes salt water and dies, the captain takes out a phone, joins the nearest board's own Wi-Fi with the owner's password, and sees which board is dead and since when. The page is read-only: it shows, it never writes or deploys. It is the one place a board listens, so it is optional, like every other module here.

One presentation, many viewers. Ten phones and three integrations cost the boards what one hub costs: the hub asks the cell once and serves them all.
Basic, or added by choice. Like the Wi-Fi extender app, the presenting module, the dashboard, phone access and every integration are optional -- some cells would find them a security liability, others filler they never use. They are off until the owner adds them, and the dashboard shows each as on, idle or not there.
The owner stays in charge. Only the owner's signed package changes what the boards do. Other programs read, and write only what the package allows.
