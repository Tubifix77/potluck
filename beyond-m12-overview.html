Potluck: one presentation of the cell

The original idea -- Kubernetes for compute and attached hardware. Every board brings its sensors, cores and memory; the hub on a PC presents them all as one machine; an integration layer lets any program see them the way it usually sees resources. 3 · Integration layer

Adapters on the API

  • each resource named in the other program's own terms
  • age and quality kept: "unavailable", not a stale number
  • writes only where the package allows; never a deploy
  • chosen per cell, like an app -- on the PC, or on a board when it must be
  • its own state shown on the dashboard

And with no PC at all

Board B is already on the house Wi-Fi. With a gateway module chosen for it, it connects out to the house's MQTT broker and presents the whole cell to Home Assistant by itself -- the same devices, the same names. Turn the PC back on and the hub takes over again.
One presentation, many viewers. Ten phones and three integrations cost the boards what one hub costs: the hub asks the cell once and serves them all.
Small boards, chosen modules. An ESP32-S3 has little memory to spare, so a cell carries only the integration modules its owner picks -- and the dashboard shows each one as on, idle or not there.
The owner stays in charge. Only the owner's signed package changes what the boards do. Other programs read, and write only what the package allows.
