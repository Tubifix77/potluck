The frame link: a CP2102 adapter on board A

As built and used on 2026-10-04 for M1, M2 and M3. The PC joins the cluster as a peer through this adapter, cabled to one board; that board reaches the others by radio. The board keeps its own USB cable for power and its console.

Four rules.
  • Use the board pins printed 17, 18 and G. Not the ones printed TX / RX on the other header: those are the console, already used by the board's USB cable.
  • Never connect the adapter's 3V3 or +5V pins to anything.
  • Never leave the adapter wired to a board while the adapter itself is unplugged. The board then partly powers the adapter through the signal wire; we saw its red LED light up.
  • Wire with everything unplugged. Then plug the adapter and the board in back to back.
step 1: one wire, TXD to RXD on the adapter. No wire to the board ground board 17 → adapter RXD (safe) adapter TXD → board 18
The adapter is the HW-598A module, pins printed top to bottom 3V3, TXD, RXD, GND, +5V, and that is how it is drawn. The board positions follow Espressif's official header table, and on these boards the printed labels matched it pin for pin. Still: find each pin by its printed label before pushing a wire on.

Setting it up

Step 1: the driver, then the adapter on its own

  • Windows needs Silicon Labs' CP210x Universal Windows Driver (v11.6.0 used). The package's .bat reported success but installed nothing; Device Manager showed the adapter with code 28. What worked: Device Manager → CP2102 USB to UART Bridge Controller → Update driver → Browse my computer → the unzipped folder. It then appears as Silicon Labs CP210x USB to UART Bridge (COMx); here, COM6.
  • Loopback: one jumper from the adapter's TXD to its own RXD. Bytes written to the port must come back unchanged; 4,096 random bytes did, at 921,600 and 115,200 baud.
  • Remove the jumper.

Step 2: ground, and the board's transmit line

  • Adapter GND → board G (J1's bottom pin, on the 17/18 side).
  • Board 17 → adapter RXD.
  • There is nothing to check yet, and silence is correct: a node only speaks to the host after the host's HELLO, and the host cannot say it until step 3.

Step 3: the adapter's transmit line, wired directly

  • Adapter TXD → board 18, one plain jumper wire like the other two.
  • Why that is safe: the CP2102's serial pins run from the chip's own supply, VDD, which is 3.0–3.6 V, and its output high is at most VDD. It cannot drive 5 V into the board. The adapter identifies itself to Windows as a CP2102. The residual risk is a counterfeit chip that copies the name and not the datasheet.
  • Check: python -m potluck.ctl --port COM6 info must report node 0x6300 … admitted. That proves both directions at once.

What it is used for

milestonecommand (from host/potluck)
M1, read another board through Apython -m potluck.ctl --port COM6 --node 7368 watch sys/uptime
M2, record a session and replay itpython -m potluck.ctl --port COM6 --node 6300 --capture s.jsonl soak --nodes 6300,7368,8160
then python -m potluck --replay s.jsonl --expect-digest <sha256>
M3, deploy a signed package to the whole cellpython -m potluck.ctl --port COM6 --node 6300 deploy pkg.json --ca ca.pub

A freshly plugged adapter can refuse its first open or miss the first HELLO for a second or two while Windows sets it up. Retry before suspecting the wiring.
