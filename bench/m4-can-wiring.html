A two-node CAN bus: boards B and C

For M4. Each board gets one SN65HVD230 transceiver module (four wires), and the two modules are joined by two more. Boards B and C keep their own USB cables, for power and for the console that records the result. Board A and its serial adapter are not part of this.

Four rules.
  • Use the board pins printed 3V3, 4, 5 and G, all on the header with 3V3 at the antenna end.
  • Board 4 → module TX, board 5 → module RX. Straight, not crossed — unlike the serial adapter. The module's TX pin is its transmitter's input; it takes what the ESP32 wants to send.
  • The module's supply goes to the board's 3V3. Never to 5V.
  • Wire with B and C unplugged, then plug them back in.
3V3 → 3.3V G → GND 4 → TX 5 → RX CANH ↔ CANH CANL ↔ CANL
The modules are drawn with the pin order you read off them: the four-pin header TX, RX, GND, 3.3V from the top, and the bus pins CANL then CANH. Which edge each header sits on is drawn for clarity, not measured. Match every wire by its printed label. The blue screw terminal carries CANH and CANL in parallel with the pins; either works for the bus.

Colours follow the usual convention: red for power, black for ground, yellow for CANH, green for CANL. Using the same colours for the real jumper wires makes the finished bench easy to check against this page.

Ten jumper wires. No resistors: each module carries its own 120 Ω terminator, which is exactly right for a bus with two nodes, one at each end.

What runs on them

  1. B and C are flashed over their own USB cables with a CAN build of the firmware (radio off): B floods the bus with lowest-priority telemetry, C sends a SAFE_STATE once a second.
  2. Both consoles report a CAN statistics line every 10 s: B counts how often its controller lost arbitration and how many SAFE_STATEs it received; C times each SAFE_STATE from submission to the wire.
  3. When the test is over, both go back to the normal firmware and the radio cell. The modules can stay wired.

Board pins: Espressif, ESP32-S3-DevKitC-1 v1.1 user guide, header J1 (positions 1 = 3V3, 4 = GPIO4, 5 = GPIO5, 22 = G), checked against board A's printed labels. Module pin order: read off the modules by the owner, 2026-10-04, agreeing with the seller's photo read from the other end. TX = the transceiver's driver input (D), RX = its receiver output (R): the module schematic, ledger row "Header pinout confirmed a second way". Termination: the 120 Ω part marked 121 on each module. Firmware pins: CONFIG_POT_CAN_TX_GPIO=4, CONFIG_POT_CAN_RX_GPIO=5.
